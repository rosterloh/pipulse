PiPulse 1.0 is a big step up from 0.1.0. There are now two pages you switch between with the miniPiTFT's buttons, a cleaner and more readable layout, and a service that runs without root.

## Highlights

- **Two pages, button navigation.** The top button (A) shows the previous page and the bottom button (B) the next one. Buttons are polled every 20 ms, so quick taps register, and a page change redraws straight away.
- **Network page.** Live Rx/Tx rates with 40-second history graphs, the peak rate over that window, and total traffic since boot for the primary interface.
- **Restyled Overview.** A larger 7×13 font with bold values, a header with the hostname, local time and page dots, dark gauge tracks so only the filled part stands out, and labelled temperature, uptime and load rows. The 1-minute load is coloured against the number of CPU cores.
- **Unprivileged service.** The systemd unit now runs as a dynamic user in the `spi` and `gpio` groups with standard sandboxing, instead of as root.
- **Clearer errors.** If the service can't start, `journalctl -u pipulse` now shows the underlying cause (for example `GPIO error: button line 23: Permission denied`) rather than just "GPIO error".

## Fixes

- Quick button presses are no longer missed (buttons were previously only read once per second).
- The backlight GPIO line is held for as long as the display is on, instead of being released straight after start-up.
- The network interface shown is now stable when several are up (e.g. `eth0` is preferred over `wlan0`), and network rates recover if the interface changes or wasn't up at boot.
- Only changed parts of the screen are redrawn each second, instead of the whole display.

## Under the hood

- Smaller dependency tree, and an optimised, stripped release binary (LTO).
- Dependencies updated: ratatui 0.30.2, mousefood 0.5.3, sysinfo 0.39, linux-embedded-hal 0.5.
- The simulator now looks and behaves like the device: a mock board with working buttons, a pixel grid, the device's 1-second update rate, and a demo mode (`PIPULSE_DEMO=1`) for screenshots.
- CI runs `cargo fmt` and `clippy -D warnings` on every PR. Dependabot updates are grouped, and releases can be started manually from the Actions tab.

## Upgrading

Install the `.deb` below on the Pi:

```bash
sudo dpkg -i pipulse_1.0.0_arm64.deb
```

The service restarts automatically. It now relies on the `spi` and `gpio` groups for hardware access, which exist by default on Raspberry Pi OS. If it fails to start, `journalctl -u pipulse` explains why.
